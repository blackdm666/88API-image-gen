# v3.0.4

修正 v3.0.3 新规则和首次配置流程的冲突。

- **首次配置恢复正常**：v3.0.3 写了「不得自己把 Key 放进命令行或环境变量」，字面上和首次配置时 Agent 自己运行 `--set-key "<KEY>"` 冲突，Agent 可能因此不敢帮用户配置。现在写明唯一例外：用户在对话里发来的 Key，可以用 `--set-key` 保存一次；从文件、环境变量或其它来源拿到的 Key 仍然禁止这样用。读配置文件、为绕过沙箱把 Key 放进命令行或环境变量，仍然禁止。
- **沙箱里 `--set-key` 写不进时给出明确提示**：DeepSeek Harness 等沙箱客户端不允许写 `~/.88api/` 时，不再抛出一长串报错，而是提示 Key 没有保存、需要客户端批准这一条命令写入，或者在客户端环境里设置 `API88_KEY`。Key 不会改存到工作目录等其它位置。技能说明同步写明：先请客户端批准这一条命令；无法批准时（例如无头运行）告诉用户，然后停止。

升级后：Codex 新建任务，Claude Code / ZCode 新开对话，以重新加载技能。
