# 项目说明

`88API-Image-Gen` 是来源于 [88api.ai](https://88api.ai/) 的图像生成插件，支持 Codex、Claude Code、ZCode、DeepSeek Harness 等能运行本机 Node.js 命令的 Agent 客户端。当前版本为 `3.0.3`，一个插件调用 88API 全部生图模型（GPT Image、az-gpt-image、Gemini / Nano Banana、Grok Imagine、Seedream、Midjourney）。88API-Nano-Banana 已停止更新，Gemini 生图并入本插件。

模型能力边界的唯一来源是 88API 文档站：各生图规范页中文 frontmatter 的 `imageModels` 生成 `https://88api.ai/helper/image-models.json`。插件读取这份清单决定端点、传法和放行的参数，不在代码里写模型表。上新模型或改参数只改文档站；只有出现新的请求方式（清单里新的 `protocol` 或 `size.param`）才需要发插件新版本。

## 模型清单

- 加载顺序：本机缓存 `~/.88api/image-models.json`（24 小时内有效）→ 联网拉取清单 → 过期缓存 → 内置快照 `scripts/image-models.snapshot.json`。只有本来就要联网的命令（付费运行、`--list-models`、`--refresh-models`、`--set-model`）才联网；`--dry-run`、`--get-config`、`--self-test`、`--job-status` 只用缓存或快照。
- 清单经 `catalog.mjs` 的 `sanitizeCatalog` 校验：`schemaVersion` 必须是 1；端点只能是 `/v1/images/generations`、`/v1/images/edits`、`/v1/chat/completions`，域名固定 `https://88api.ai`；不合格的模型条目被丢弃，整份清单不可用时改用缓存或快照。
- `resolveRequestPlan` 把 `--aspect`、`--resolution`、`--quality`、`--background`、`--output-format` 按条目换算成请求字段（`size` 像素 / `aspect_ratio`+`resolution` / 档位 / `--ar` / `image_config`），不支持的取值在付费前报错。`selectEditVariant` 按参考图来源（本地文件 / URL）和张数选出编辑请求方式并检查上限。
- `--list-models` 调用免费的 `GET /v1/models`，按 Key 标出 `available`。`--model` 指定清单没有、但 Key 能用的生图模型时，`inferEntry` 生成保守条目：只发提示词和参考图，不发尺寸和质量参数。
- 发版前用 `curl -s https://88api.ai/helper/image-models.json -o plugins/88api-image-gen/skills/88api-image-gen/scripts/image-models.snapshot.json` 更新内置快照。

## 配置契约

配置文件默认位于 `~/.88api/image-gen.json`（环境变量 `API88_CONFIG_DIR` 可改目录）。新路径不存在时依次读取旧路径 `~/.codex/88api-image-gen-config.json`、`~/.codex/fhl-image-gen-config.json`、`~/.88api/nano-banana.json`、`~/.codex/88api-nano-banana-config.json` 并复制到新路径，旧文件不删除；`~/.codex/88api-image-gen-config.json` 存在期间，每次保存同时更新它，供未升级的旧版插件使用。环境变量 `API88_KEY` 优先于配置文件，只在本次进程中使用、不写盘。插件公开使用一个 `auto` 分组 Key；旧多 worker 配置仍可读取，但运行只选择第一个启用 Key，再次执行 `--set-key` 后会收敛为单 Key。

模型优先级：单次 `--model` > 保存的 `model` > `gpt-image-2`。旧配置中的已移除模型会在加载时迁移为 `gpt-image-2`；`gpt-image-2-4k` 迁移为 `gpt-image-2` 并保存 `resolution: "4K"`。分辨率优先级：单次 `--resolution` > 快速 / 批量模式保存的 `resolution`（旧配置的 `quality`）> 顶层 `resolution` > 清单的 `defaultResolution`。

真实 Key 只允许保存在用户本机配置，不得出现在源码、文档、提交、Release、日志或聊天回复中。`--get-config` 只显示活动 Key 的脱敏摘要。

## API 与安全边界

- 端点、上传格式和参考图上限由模型清单决定：Images API 模型用 `POST /v1/images/generations` / `POST /v1/images/edits`（multipart 或 JSON）；Gemini 用 `POST /v1/chat/completions`，比例和分辨率写在 `extra_body.google.image_config`。
- 不调用 `/v1/responses`，失败后不换端点、不换模型。
- 按像素出图的模型（`size.param = size`）在付费请求前检查 16 像素对齐、最大边 `3840`、最大宽高比 `3:1`、总像素 `655360～8294400`，并保留提示词末尾的画幅提醒和本地 PNG 裁切；其它模型按返回结果原样保存。
- 不支持的比例、分辨率、参数和参考图张数在本地终止，不发起付费请求。
- 已受理或状态未知的请求使用 `[NO-AUTO-RETRY]`，不得自动重发；用户明确授权后可作为一次新的付费请求重新提交。
- 请求超时 600 秒。失败按阶段报告：连不上服务器（`request was not sent`，未发出、未扣费，可自动重试）；提交后状态未知（`stage: submit`）；已收到响应但读取失败（`stage: read-result`，已扣费）；结果图下载失败（`stage: download`，已扣费）。
- 结果是链接时，下载前先把链接写入输出目录的 `*.pending-download.json`，免费重试 3 次（间隔 2 秒、5 秒），成功后删除；仍失败时保留该文件，`--retry-download <文件>` 只下载、不发新的付费请求。
- `--dry-run` 不要求 Key、不调用付费 API、不输出图片 Base64。
- 每次付费运行在 `~/.88api/image-gen-jobs/<任务号>.json` 写提交记录：每个请求发出前记为 `submitting`，收到响应后记 HTTP 状态，结束时记为 `saved` / `not-sent` / `rejected` / `unknown` / `billed-not-saved` / `empty-result`。进程被客户端超时强行结束时，记录停在 `submitting` / `responded`，`--job-status` 会报告为 `interrupted`（`[NO-AUTO-RETRY]`，可能已扣费）。没有发出任何请求的运行不保留记录。
- `--json` 在付费运行结束时向 stdout 输出一行与 `--job-status` 相同结构的 JSON。
- 付费运行结束时设置退出码并让进程自然退出，不在网络请求后直接调用 `process.exit()`（Windows 上 Node 24 会触发 libuv 断言，退出码变成 127）。
- 两张及以上图片必须由一次插件进程通过 `--count`、`--repeat`、`--batch-inline` 或 `--batch` 调度，避免 Auto 模式为每张图片重复申请外网执行审批。
- 客户端命令超时（Claude Code 默认 2 分钟、最多 10 分钟等）可能在请求已被受理后结束进程；技能要求 Claude Code 把付费命令放到后台运行，任何客户端中断后都先查 `--job-status`，不得盲目重发。
- Codex 外网执行授权、沙箱网络权限或审批服务 429 属于插件进程之外的前置失败。明确尚未启动的任务没有发送到 88API，不会产生对应的 88API 日志或费用；不得将其描述为 88API 限流。
- 技能会提示用户自行在 **General（通用）→ Permissions（权限）** 启用并选择 **Full access（完全访问）**，同时说明该模式会取消本地沙箱与审批边界。插件不得自动修改用户的 Codex 权限配置。

## 开发与发布验证

```powershell
node plugins/88api-image-gen/skills/88api-image-gen/scripts/generate.mjs --self-test
node plugins/88api-image-gen/skills/88api-image-gen/scripts/generate.mjs --list-models
node plugins/88api-image-gen/skills/88api-image-gen/scripts/generate.mjs --resolve-size --model gpt-image-2 --aspect 16:9 --resolution 4K
node plugins/88api-image-gen/skills/88api-image-gen/scripts/generate.mjs --model gemini-3-pro-image --prompt "probe" --aspect 3:4 --resolution 2K --dry-run
node plugins/88api-image-gen/skills/88api-image-gen/scripts/generate.mjs --model grok-imagine-image --prompt "probe" --aspect 21:9 --resolution 2K --dry-run
claude plugin validate plugins/88api-image-gen
claude plugin validate .
```

发布流程为开发分支 → draft PR → ready → squash merge → annotated tag → GitHub Release，不直接推送 `main`。

升级后新建 Codex 任务 / Claude Code 或 ZCode 新对话，以重新加载技能清单。
